# Лабораторная работа №1 — Цветовые модели

**Дисциплина:** Программирование компьютерной графики  
**Вариант:** 10  
**Подгруппа:** 10А  
**Преобразования:** `CMYK ↔ LAB ↔ RGB`

## 1. О проекте

Проект представляет собой статическое веб-приложение для интерактивной работы с цветом одновременно в трех цветовых моделях: **CMYK, LAB и RGB**.

Пользователь может менять цвет в любой из трех моделей, после чего значения в двух остальных моделях автоматически пересчитываются. Все математические преобразования реализованы вручную на JavaScript, без библиотек конвертации цветов.

XYZ используется только как внутреннее промежуточное представление для преобразований между RGB и LAB и не выводится в основной интерфейс.

---

## 2. Реализованный функционал

### 2.1. Работа с тремя цветовыми моделями

В интерфейсе одновременно отображаются:

- **RGB** — компоненты `R`, `G`, `B`;
- **CMYK** — компоненты `C`, `M`, `Y`, `K`;
- **LAB** — компоненты `L*`, `a*`, `b*`.

При изменении любого значения все остальные представления цвета обновляются автоматически.

### 2.2. Три способа задания цвета

Для каждой модели доступны три способа изменения цвета:

1. **Числовой ввод** — точное значение каждой компоненты.
2. **Ползунки** — плавное изменение координат цвета.
3. **Системная палитра** — выбор цвета через стандартный `input[type="color"]` браузера.

Диапазоны компонентов:

| Модель | Компоненты | Диапазоны |
|---|---|---|
| RGB | R, G, B | `0…255` |
| CMYK | C, M, Y, K | `0…100 %` |
| LAB | L* | `0…100` |
| LAB | a*, b* | `-128…127` |

### 2.3. Автоматический пересчет

В зависимости от модели, которую редактирует пользователь, используются следующие цепочки:

```text
RGB
├──→ CMYK
└──→ XYZ ──→ LAB
```

```text
CMYK ──→ RGB ──→ XYZ ──→ LAB
```

```text
LAB ──→ XYZ ──→ RGB ──→ CMYK
```

После каждого изменения интерфейс получает новое согласованное состояние всех трех моделей.

## 3. Освещение D65, D50 и E

В приложении можно выбрать один из трех стандартов освещения:

- **D65** — средний дневной свет, стандартный для sRGB;
- **D50** — теплый дневной свет, используемый в полиграфии;
- **E** — равноэнергетический источник.

### 3.1. Динамический расчет RGB ↔ XYZ

Готовые матрицы `RGB ↔ XYZ` в рабочем коде не хранятся.

Матрица строится во время выполнения программы из:

- координат основных цветов sRGB;
- точки белого выбранного источника освещения.

Используются sRGB primaries:

```text
R: x = 0.64, y = 0.33
G: x = 0.30, y = 0.60
B: x = 0.15, y = 0.06
```

Алгоритм построения:

```text
1. Для R, G и B строятся XYZ-координаты основных цветов.
2. Формируется первичная матрица P.
3. Вычисляется точка белого W выбранного источника.
4. Находится вектор масштабов S = P⁻¹ × W.
5. Получается матрица RGB→XYZ = P × diag(S).
6. Обратная матрица XYZ→RGB вычисляется как обратная к RGB→XYZ.
```

Для D65 используется белая точка из предоставленных материалов:

```text
Xn = 95.047
Yn = 100
Zn = 108.883
```

При смене D65 / D50 / E матрицы автоматически рассчитываются заново.

## 4. Преобразование RGB ↔ XYZ

Реализация находится в:

```text
src/model/rgb-xyz.js
```

### 4.1. RGB → XYZ

Сначала значения sRGB переводятся из нелинейного пространства в линейное по кусочной функции sRGB:

```text
x <= 0.04045:
    x / 12.92

иначе:
    ((x + 0.055) / 1.055)^2.4
```

После этого линейный RGB умножается на динамически рассчитанную матрицу `RGB→XYZ`.

### 4.2. XYZ → RGB

Выполняется обратное матричное преобразование, затем линейные RGB-компоненты кодируются обратно в sRGB:

```text
x <= 0.0031308:
    12.92 × x

иначе:
    1.055 × x^(1/2.4) - 0.055
```

---

## 5. Преобразование XYZ ↔ LAB

Реализация находится в:

```text
src/model/xyz-lab.js
```

LAB рассчитывается относительно точки белого **текущего выбранного источника освещения**.

Основные формулы:

```text
L* = 116 × f(Y / Yn) - 16

a* = 500 × (f(X / Xn) - f(Y / Yn))

b* = 200 × (f(Y / Yn) - f(Z / Zn))
```

Также реализовано обратное преобразование:

```text
LAB → XYZ
```

Это позволяет использовать LAB как полноценную редактируемую модель, а не только как отображаемый результат.

---

## 6. Преобразование RGB ↔ CMYK

Реализация находится в:

```text
src/model/rgb-cmyk.js
```

### 6.1. CMYK → RGB

Используются формулы:

```text
R = 255 × (1 - C) × (1 - K)
G = 255 × (1 - M) × (1 - K)
B = 255 × (1 - Y) × (1 - K)
```

где `C`, `M`, `Y`, `K` предварительно переводятся в диапазон `0…1`.

### 6.2. GCR

**GCR (Gray Component Replacement)** заменяет общую серую составляющую CMY на черный канал K во всем диапазоне цветов.

В качестве серой составляющей используется:

```text
K = min(C, M, Y)
```

После выделения K цветные компоненты пересчитываются так, чтобы обратное преобразование CMYK→RGB сохраняло исходный RGB-цвет.

### 6.3. UCR

**UCR (Under Color Removal)** вводит черную компоненту преимущественно в глубоких тенях.

В интерфейсе доступен параметр **«Порог UCR»**. Если общая нейтральная составляющая ниже порога, K не добавляется. После превышения порога черная компонента постепенно увеличивается.

Параметр порога отображается только при выборе алгоритма UCR.

## 7. Обработка выхода за RGB-gamut

При преобразовании из LAB в RGB могут появиться значения меньше `0` или больше `255`.

Для таких случаев реализованы две стратегии.

### 7.1. Clipping

Каждая компонента отдельно ограничивается диапазоном:

```text
0…255
```

Пример:

```text
RGB(-20, 120, 300)
→ RGB(0, 120, 255)
```

### 7.2. Scaling

Вместо независимого обрезания весь диапазон RGB линейно масштабируется общей формулой так, чтобы минимальное и максимальное значения попали в допустимые границы.

Пример:

```text
RGB(-20, 120, 300)
→ RGB(0, 111.56, 255)
```

### 7.3. Синхронизация после gamut mapping

После применения Clipping или Scaling скорректированный RGB считается **фактическим отображаемым цветом**.

Затем из него повторно рассчитываются:

```text
RGB → XYZ → LAB
RGB → CMYK
```

Это исключает ситуацию, когда RGB уже был скорректирован, а LAB продолжает описывать исходный недостижимый цвет.

При выходе за gamut в интерфейсе выводится предупреждение с исходными RGB-координатами до обработки и названием примененной стратегии.

## 8. Динамические градиенты ползунков

Фон каждого ползунка рассчитывается динамически.

При построении градиента:

1. берутся текущие значения всех компонент модели;
2. изменяется только компонента конкретного ползунка;
3. для каждой промежуточной точки выполняется полное преобразование в RGB;
4. полученные RGB-цвета используются для построения CSS `linear-gradient`.

Поэтому градиент каждого канала зависит от текущего состояния остальных каналов.

Например, при изменении `R` в RGB градиенты `G` и `B` автоматически перестраиваются с учетом нового уровня красного.

## 9. Архитектура проекта

Код разделен на три независимых слоя.

### 9.1. Model

Папка:

```text
src/model/
```

Содержит только математическую логику и ничего не знает об интерфейсе.

Основные файлы:

```text
math.js          — операции с матрицами и вспомогательная математика
illuminants.js   — D65 / D50 / E и динамический расчет матриц
rgb-xyz.js       — RGB ↔ XYZ
xyz-lab.js       — XYZ ↔ LAB
rgb-cmyk.js      — RGB ↔ CMYK, GCR и UCR
gamut.js         — Clipping и Scaling
color-model.js   — объединение преобразований в единый интерфейс
```

### 9.2. View

Файл:

```text
src/view/color-view.js
```

Отвечает за:

- создание блоков RGB, CMYK и LAB;
- числовые поля;
- ползунки;
- палитры;
- отображение текущего цвета;
- предупреждения;
- динамические градиенты.

Математические формулы преобразования цветов здесь не реализуются.

### 9.3. Controller

Файл:

```text
src/viewmodel/color-controller.js
```

Связывает интерфейс и математическую модель.

Controller:

- хранит текущие настройки;
- определяет, какая модель была изменена пользователем;
- передает значения в Model;
- получает согласованное состояние всех моделей;
- передает новое состояние во View;
- управляет D65/D50/E, GCR/UCR, порогом UCR и стратегией gamut mapping.

## 11. Автоматические тесты

Требуется Node.js 18 или новее.


или под Windows:


В текущем наборе предусмотрено **15 автоматических проверок**.

Проверяются, в частности:

## 13. Исследование цветового графика МКО

В основном интерфейсе график МКО не выводится, чтобы не перегружать приложение элементами, не требуемыми непосредственно для редактирования цвета.

Исследование цветового графика МКО приведено в сопроводительной документации.

В проекте также вычисляются координаты цветности:

```text
x = X / (X + Y + Z)
y = Y / (X + Y + Z)
```

Эти значения позволяют анализировать положение цвета на диаграмме цветности и объясняют существование цветов XYZ/LAB, которые невозможно напрямую представить внутри RGB-gamut.
